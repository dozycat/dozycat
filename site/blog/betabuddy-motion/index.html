那个小人，爬得不像人

最短路算出来的走法，人不一定做得出来。给模型补上重心、铅垂线和抛物线，再请十七位看不到代码的复查者轮流挑刺：小人是怎么一点点爬得像个人的，以及哪里还不像。

上一篇写的是怎么把一座岩馆装进手机：量墙，认岩点，把“怎么爬”做成一个最短路问题。小人能从起步点一路走到结束点，换一副身材，走法跟着变。

然后我盯着它看了很久，越看越不对劲。

它会双脚悬空挂在一个点上，身体歪在一边，一动不动。它会空着两只手，踩着踢脚板横着走一米多，再起跳。它跳起来的时候像在月球上，飘过去的。

最短路只管哪条路代价最小，不管牛顿。这篇手记写的是后来怎么一点点把牛顿请回来：怎么建的模，路上撞到了什么，哪些解决了，哪些没有。

先找一个不认识这份代码的人来看。

改之前得先知道哪里不像。我自己看不出来了，写代码的 agent 也看不出来：每个动作它都知道“为什么是这样”，看什么都觉得有道理。

所以定了一个规矩。每改完一轮，起一个全新的 agent 当复查者。它看不到代码，看不到文档，也不知道这一轮改了什么。它手里只有导出来的骨架坐标，和一个能把骨架画成三视图的工具。任务只有一句话：从图和数字判断，这是不是真人做得出来的动作。别客气。

复查者会自己写脚本量东西。第一次认真量那些动态动作，出来三个数：

  • 腾空的时候，重心往下掉的加速度是 2 到 4 m/s²。地球上是 9.8。
  • 起跳速度 3.7 到 5.8 m/s。顶尖运动员原地纵跳，离地时大约是 3.7。
  • 双脚悬空、基本不动的 1342 帧里，有 1127 帧身体偏在手点正下方 8 厘米以外。

三个数，三处都不是这个星球上的事。

前后一共复查了十七轮。下面按建模的顺序讲。

挂着的人是一根铅垂线。

原来的模型判断“稳不稳”只看脚：重心落在脚的支撑范围外面多少，手就得扛多少。脚一离点，这套算法就没了抓手，身体停在哪儿都算数。

可是没有脚的时候，人就是一个摆。静止下来，重心一定在手点的正下方，没有别的可能。

所以第一件事是把重心算对：按各段肢体的质量加权，躯干占一半，头 8%，一条大腿一成，小腿加脚 6%。然后加一条硬规则：没有脚受力的姿态，重心必须挂在手点下面；手上的负担有上限，原来放到 2.5 倍，现在收到 1.6 倍。

这条规则一加，一批“解”就没了。它们本来也不该有。

跳，是一道中学物理题。

够不着的时候可以跳。原来的跳只是一条特别贵的边，画面上是把身体从这儿匀速挪到那儿。现在每一跳都要先算一遍：

T   = Math.sqrt(2 * need / g)             // 手还差多远，就得飞多久
v0  = [d.x / T, d.y / T + g * T / 2, d.z / T]   // 离脚那一刻的速度
vC  = [v0.x, v0.y - g * T, v0.z]          // 手到点那一刻的速度
lam = 1 + (|vC|² + 2 * g * drop) / (g * len)    // 荡到最低点，手上有几倍体重

need 是起跳姿态下，肩离“够得着那个点”还差的距离。起跳速度不能超过这副身体的上限，上限由爆发、体重和脚点好坏决定。抓住之后如果没有脚，人会荡下去，荡到最低点时手上最重；那个点得够好，才挂得住。

抓住之后的摆荡是一个有阻尼的摆：带着接住那一刻的速度，荡过手点正下方，再荡回来，每荡半个来回，幅度剩四成多。

还有一种跳，一只手一直留在原来的点上。那不是自由落体，那只手在帮忙拉。做法是把重力打个折：那只手能担多少体重，重力就减掉多少。同样的起跳速度，能飞得更远一点。

求解器判断“这一跳做不做得到”和画面上播的，是同一组数。这一点很重要，后面会看到它不成立的时候会出什么事。

有趣的事一：那只踩着“地面”的脚，离地两米。

查静态动作的时候发现一件怪事：两百多个关键帧里，标着“脚在地面”的那只脚，其实悬在垫子上方，最高的悬了两米多。

原因很好笑。状态里的“地面”只是一个名字。另一只脚踩上岩点、人站起来之后，这只脚早就离地了，但名字没改。而“脚在地面”的状态有优待：单脚站立的限制、空手扶墙的限制，都管不到它。于是模型找到了一个漏洞，带着一只名义上在地面的脚，一路爬到了两米高。

修法是一句话：叫“地面”的脚，必须真的踩得到垫子，踮脚为限。

修完，一批线的起步走不通了。因为真人从垫子上墙，靠的是一个模型里原本没有的动作：一只脚先踩上点，另一只脚在垫子上一蹬，人就上去了。于是补了这个动作。垫子上的腿先屈再伸，手在身体升到一半时离开原处，够得着新点就抓住。

有趣的事二：最后一帧，膝盖突然直了。

有一轮复查者说：起跳前最后一帧，膝还弯着 130°，下一帧人已经在空中，腿直了。真人的腿是蹬直了才离地的。

我当成 bug 追了半天，一度以为是哪次改动把膝角改坏了。最后发现改动没问题，是几何。

腿快伸直的时候，膝角对距离极其敏感。膝从 130° 张到 170°，髋只需要再远离脚七厘米。而起跳前那一瞬间，身体每秒走两三米。七厘米，就是一帧。

导出的帧隔 0.04 到 0.1 秒，最后一个“脚还在点上”的帧，可能离真正离脚还差大半帧。腿确实蹬直了，只是蹬直的那一下落在两帧之间。

这件事教会我两点。一是给复查者的说明里要写清楚采样间隔。二是它也没有完全冤枉我：腿伸直的过程挤在最后几十毫秒里，说明蹬伸这一段的速度是怎么来的，本身就有问题。这一点到最后也没改好，后面说。

有趣的事三：矮的能爬，高一点的反而不能。

有一个很便宜的检查：固定一副身材，每次只动一个滑块，把 70 条线都算一遍。道理上，人高一点、力量大一点、柔韧好一点，能爬的线只会多，不会少。

结果有一条线，150 厘米能解，158 厘米无解。

追下去是求解器里一个很老实的偷懒。起步规则是“双手在起步点、双脚在地上”。如果站在垫子上两只手都摸得到起步点，求解器就只保留这一种起法。158 的人手臂伸直，刚好摸得到。可手臂已经伸直了，人蹲不下去；蹲不下去，就跳不起来。150 的人反倒没事：他根本摸不到，求解器给他留了另一种起法，先扶着墙蹲下，再跳上去抓。

高个子被“摸得到”害了。修法是两种起法都留着，让最短路自己挑。

同一个检查还揪出另一个洞：静态走法双脚离不了地的时候，求解器直接跳过了“勾脚”那一遍。有的线恰恰是靠脚跟勾住一个低处的点，把人带离地面的。

修完这两处，不单调的情况从 4 处降到 1 处，示范者身材能解的线从 68 条变成 69 条。

有趣的事四：手抓住的那一帧，人弹了 16 厘米。

除了看图的复查者，还有一个 agent 专门在 iOS 模拟器里操作真的 App：真的点屏幕，真的播放，每 40 毫秒采一次骨架。它报告说，有一步跳，手抓住点的那一帧，骨盆在一个采样里挪了 16 厘米。

我在导出的数据里复现了，17 厘米，对得上。

原因是同一个时刻有两副骨架。起跳那一刻身体离墙多远，画面用的是“手还抓着点”的那副，往后坐着；求解器算重心用的是“手已经松开”的那副。两副骨架差了将近 20 厘米。腾空的时候这段差被悄悄补上了，到接住那一帧，又按原来的偏移摆了回去。

上一篇我很得意地写过：算的和画的是同一副骨架，所以不会对不上。这句话在跳的那零点几秒里不成立。

同一类问题还有一个：腾空时躯干一直保持起跳时往后坐的姿势，肩比求解器以为的离墙远了二三十厘米。于是接住那一刻手根本够不着点，整个人被拽过去。

修法都一样朴素：从上一帧实际在的地方接着走，别相信另一套数。

有趣的事五：两位复查者，同一份代码，结论相反。

第十五轮，复查者说双手起跳“大体像”。我以为到头了。

第十六轮换了一个复查者。起跳的代码一行没动，结论是“不像”，并且附了一长串数字。

更尴尬的是另一件事。写代码的 agent 自己也量：离脚前后速度对不上的跳，57 步里只有 4 步。复查者量：23 步。

差在量法上。它量的是动画内部“蹬伸”这一段的首尾；复查者量的是导出帧上的重心，把腿最后蹬直那一下也算了进去。自己出题自己答，分数当然好看。

后来的做法是把复查者写的量测脚本原样拿过来，先在同一份数据上复现它的每一个数，一个不差，再用它当尺子去改。尺子得是别人的。

改完之后。

再列几样具体改了的：

  • 两只手不是同时松的。身体往一边去，远的那只先够不着、先松，近的那只拉到最后。
  • 起跳要有真的蹬伸距离。有一步是站在垫子上、腿几乎直着，“跳”出了 2 m/s，蹬伸的路程只有 8 厘米。这种跳被筛掉了。
  • 跳完找回脚更快。人挂在手上是费力的，够得着就搭。复查者量到的悬空时间，中位数从 3 秒降到 2 秒出头。
  • 悬空时屈臂锁多深，看力量。

没解决的。

  • 双手都离点的那种跳，从松手到离脚的零点几秒，最后一轮复查仍然是“不像”。手松得早，速度挤在最后一格，手臂没有领着身体去够点。这一段是照着一条给定的曲线画出来的，没有“腿在蹬、手在拉、合起来把人加速”这件事本身。再往下，得按人体的动力学去合成，不是调参数能调出来的。
  • 从垫子起跳也还是“不像”。数据里只剩三步，一步是真的蹲跳，另外两步不是。
  • 力量是按“绝对力量 ÷ 体重”算的，体重轻的人占便宜。46 公斤、力量 5 的身材，比值相当于 65 公斤的人力量 8.8，所以小个子会悬空做很深的引体。该按肌肉横截面修正，还没做。
  • 静态动作里，躯干偶尔一帧跳十几厘米的毛病，从 58 步压到 20 步。代价是蹭在墙上的脚多滑了几次。
  • 这一轮的改动还没发版，也没在真机上跑过。

所以 App 里那句话还得留着：这是模型的推演，不是教练建议。

这一轮是怎么干的。

和上一篇一样，代码是 coding agent 写的。不一样的是这次不止一个：一个改求解器和动画，一批互不相识的复查者轮流看图挑刺，还有一个在模拟器里点屏幕。

我说的话更少了，大概就这几句：

“有些动作不是人能做出来的。”“有的走法像在抓空气，看不到点。”“最短路不一定是最好的走法。”“矮个子有些线解不出来，把爆发调满也不行，为什么？”

上一篇的结尾说，写代码不是瓶颈了，知道什么才算对才是。这一轮的体会往前挪了半步：什么算对，最好别让做题的人自己说了算。找一个看不到答案的人，让他自己带尺子来。

哪怕他是另一个 agent。
