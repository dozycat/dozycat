疲劳感知 — 观测你干得多累，不观测你在干啥

懒猫怎样只凭输入节奏、在位状态与活动类别感知疲劳，同时不记录键值、不截屏，也不读取窗口内容。

真人这个 agent 的输入，是对屏幕和设备的持续观测。这套架构承自 pb-os（~/workspace/cat，apps/paperboy/plugins/pb-os/ARCHITECTURE.md）：采集器把原始数据收进一个私有的 L0，经过唯一一道 raw→semantic 的边界，投影成一条很小的语义流。pb-os 的铁律是原始击键和截图永远不出守护进程。dozycat 把这条边界又往里收了一档：采集层本身就是内容盲的。pb-os 想知道你在干啥（context window），dozycat 只想知道你干得多累（labor window）——键入了什么、屏幕上有什么，一概不需要；需要的只有强度、节奏、时长。

它看得见什么

击键、点击、滚动，看的都是频率，不是内容——用的是CGEventSourceCounterForEventType，一个系统级计数器，不是事件流，连辅助功能权限都不用申请，天然只有数字没有键值。空闲了多久，问CGEventSourceSecondsSinceLastEventType。前台是哪个 app、切换得多不多，v0 用lsappinfo，v1 换成 NSWorkspace 通知；读的是 app 名，不碰窗口内容。在不在开会，v0 靠前台 app 猜（Zoom、Teams、FaceTime、腾讯会议这些），v1 改看麦克风和摄像头的占用（CoreAudio / AVCapture）——比 app 名可靠，而且给出的只是一个布尔。日历在v1 经 EventKit 只读忙闲，「三点有会」可以提前留体力。手机那侧走 HealthKit（睡眠、步数、心率变异）和 DeviceActivity；iOS 没法持续观测屏幕，桌面算出的疲劳状态经记忆同步流到手机上去（见 MEMORY-SYNC.md 的 energy 与 ledger）。

写进产品文案的隐私承诺，一句话：无键值记录、无截屏、无窗口内容读取；所有原始计数不出本机，跨设备只同步「能量数字 + 事件」的密文。 v2 的两枚新信号不破这条承诺：摄像头帧过一遍人脸检测即弃（跨边界只有在/不在），活动类别是从 sequence管线借来的一个六选一标签（OCR 文本本就留在 pet，见 MOMENTS-PIPELINE.md）。

能量怎么算（实现与唯一事实来源：dozycat-sense/src/lib.rs 的 tuning）

能量只有一个写者：Rust 模型的 EnergyModel::step，每分钟结一次账。Swift 侧谁都不改数字——回血清单的「现在做」只记次数、二十分钟后回来量自然回了多少，胶囊和菜单栏只是展示。所以对账只需要看一个文件。

每分钟聚一个采样，先折算劳动强度 i ∈ [0,1]：

i = clamp( 0.5·min(keys/300, 1) + 0.3·min((clicks+scrolls)/60, 1) + 0.2·min(switches/6, 1) )
会议分钟：i = max(i, 0.7)     // 开会是持续的高强度输出，哪怕手不动

支出。 生理掉在「坐着本身 + 输出量」上：活跃的每分钟掉 0.10 + 0.25·i，摸鱼约合每小时 6 点，高强度约 21 点；被动在座（摄像头见人、手不动）每分钟掉 0.03，约合每小时 2 点——生理不看你在干什么，只看你坐着没起身。心理掉在执行功能的开销上：基础加切换 (0.05 + 0.20·switch)，再乘活动系数（深度产出1.2、沟通 0.9、浏览 0.8、娱乐 0.5），会议叠加 0.25，连续活跃超过一小时再叠加0.10；被动在座刷视频、翻网页时心理每分钟回 0.05——歇的是脑子，不是身体。

收入。 回血要等真的离开：键鼠连续空闲满 3 分钟起算，摄像头确认没人只等2 分钟（证据硬）。起算后的前 10 分钟是短憩红利：生理每分钟 +1.0、心理+0.5——接杯水、走两步这种短休息，恢复效率最高（微休息文献的同款结论）；10 分钟之后回到常速 +0.5 / +0.3，躺一下午不会和四次短憩一个价。红利跟着「本次休息」走，中途回来敲一下键盘就重新计。没有这笔红利的话，提醒让人「去接杯水」、账上却几乎不奖励，反馈环是断的。会议中一分钟都不回血。

一笔可以口算的账：站起来歇一刻钟 = 3 分钟确认 + 10 分钟红利 + 2 分钟常速≈ 回 11 点生理——胶囊文案「站起来歇一刻钟，能回十来点」说的就是它。天花板 100，地板 0；夜里的睡眠（iOS/HealthKit）负责重置。UI 的两道警戒线：生理跌破 50 胶囊和菜单栏的数字变珊瑚色，跌破 30 猫开口提醒。

v2：摄像头在位 + 活动类别（细化算法）

v0 有个结构性的盲区：它把「没有输入」当成「人走了」。于是看视频、读长文、停下来想事，全被误判成休息在白白回血；反过来，真正的久坐提醒只认打字的90 分钟，刷两小时视频它一声不吭。v2 引入两枚新信号把这个洞补上，代价严格控制在两枚语义原子上——摄像头在位是一个布尔，活动类别是六选一的标签，画面帧和 OCR 文本都不跨进程边界。

在位（摄像头，设置里默认关）。 pet 侧开一条低分辨率会话，30 秒抽一帧过Vision 人脸检测，帧在内存里活到检测完为止——没有截图、没有落盘，跨过边界的只有 true/false。开启期间摄像头指示灯常亮，这是诚实的代价，设置文案写明。授权走系统相机权限，拒绝或关闭时信号缺席，模型退回 v0 的纯键鼠推断。

活动类别（OCR 语义，借 sequence 管线）。 前台 app 名每 30 秒免费分一档（微信/Slack → 沟通，Xcode/Cursor → 深度产出，IINA/bilibili 客户端 → 娱乐，会议 app → 会议，浏览器 → 浏览）；sequence 每 5 分钟带着屏幕 OCR 跑的那一趟做精分类——浏览器里开会、网页里刷视频，页面文字比 app 名诚实。分类是纯规则（ActivityClass.classify，SenseHints.swift），不过模型、不出设备；分不清就unknown，宁缺毋滥。

两枚原子经 ~/.dozycat/sense_hints.json 交给 dozycat-sense，各带时间戳和保鲜期：在位 90 秒（两个采样周期没更新就作废），活动 8 分钟。过期即 unknown——任何信号缺席，模型都退化回 v0 语义，老的七个测试原样通过就是这条退化路径的证明。

融合之后（EnergyModel::step，v2），每一分钟落进三种处境之一。「在座」的定义是手在动或者摄像头见人，「离开」是摄像头没人而且手不动，会议则取 app启发式与活动分类的并集——浏览器里开的会，页面文字认得出。

手在动的分钟照 v0 按强度掉生理，心理损耗则乘上活动系数：深度产出 1.2，沟通0.9，浏览 0.8，娱乐 0.5。同样的键速，写代码比在微信聊天磨脑子——心理损耗的本质是执行功能的开销，聊天有社交负荷但执行负荷低，刷视频的时候脑子干脆在放松。生理损耗刻意不看类别：坐着就是坐着，身体不在乎你在干什么。

在而不动的分钟——读文档、看视频、停下来想事——是 v2 真正新出来的处境：不回血。身体还坐着，生理每分钟照磨 0.03（约合每小时两点）；看视频和浏览时心理每分钟回 0.05，因为歇的是脑子，不是身体。v0 会把这些分钟全数错判成休息。

真的离开了，摄像头确认的离开只等两分钟就起算回血，比纯键鼠推断的三分钟快一步——「没人脸」比「没输入」证据硬，停下来想事不会被误判成走了。没开摄像头就沿用 v0 的保守推断。

久坐提醒也跟着换了骨架：从「连续活跃分钟」换成「连续在座分钟」。摄像头在位时，刷九十分钟视频和写九十分钟代码一样会被请起身——身体不区分这两件事。低电量提醒同理从「活跃」放宽到「在座」。

常数都在 dozycat-sense/src/lib.rs 的 tuning 模块，测试从产品逻辑倒推着写（TDD），盖住的典型日子：看一晚上视频（不回血、心理微回、90 分钟照样提醒起身）、摄像头确认离开（回血比纯推断早一分钟）、一小时微信 vs 一小时深度产出（心理差距拉开、生理分毫不差）、浏览器里开的会（OCR 认出、散会照样提示补血）；短憩红利那笔账单独一组——一刻钟回十来点（胶囊文案的数字直接来自这条断言）、中断后红利重新计、久躺边际递减、会议中零回血、天花板夹得住。

它什么时候开口

连续活跃满 90 分钟，它说「坐了 N 分钟啦，去接杯水回血？」。会议态持续了 20 分钟以上、又连续 3 分钟消失（中途切出去记笔记不算散会），它说「会开完了吧？高强度输出后要补血，起来走两步～」。生理掉破 30，它说「生理能量掉到 N 了，眼睛离开屏幕一会儿好不好？」。切换率居高不下、心理在磨损，它说「感觉你在好多事之间跳，挑一件收个尾？」。同类提醒之间隔至少 45 分钟，永远不弹连环——懒猫轻轻说一次就好。

数据从哪来、落到哪去

dozycat-sense（桌宠进程内一个线程，5s tick → 1min 聚合）
  → EnergyModel.step() → JSONL 语义流
      ├─ Minute … 桌宠 UI（菜单栏「懒猫 45」、猫的气泡）
      └─ Nudge  … 弹卡（设计稿 08）/ 通知
  → 写入 dozycat-core 的 energy + ledger → 同步 → iOS「今日」页实时同款数字

v0 已经跑起来的：计数采集、强度折算、能量模型、带冷却的 nudge 引擎、JSONL 输出；能量落进了 dozycat-core 的账本（DOZYCAT_STORE，默认 ~/.dozycat/store.db），重启从账本接着算——跨端合并后最新一条可能来自手机，桌面直接续上。v2 加上了摄像头在位与活动类别（上文），hints 文件是 pet → sense 的唯一新通道（DOZYCAT_HINTS，默认 ~/.dozycat/sense_hints.json）。cargo test 盖住了典型的日子：高强度编码、长会加会后提醒、离开回血，以及 v2 的看视频不回血、摄像头离开、微信 vs 深度产出、浏览器里的会。往后排的：麦克风占用检测替掉 app 启发式、NSWorkspace 通知、EventKit 的前瞻、iOS 把 HealthKit 写进同一本账；v3 的候选是用同一路人脸检测顺带出眨眼频率和视线离屏比例（Vision landmarks 都是现成的），给「眼睛该歇了」一个真信号，以及把活动类别的规则表交给 dream agent 按用户的实际 app 谱系慢慢学。
